Chatbot or agent · one layer · linked chart panels

A map with linked charts, in one link

The map spec's charts list opens chart panels beside the map when the link opens. Each chart names its layer, its fields and its look; the numbers are counted from the live layer in the browser, so the link stays short and carries no data. The map colours the ten states with the most incidents and the bar chart takes the same colours; hovering a bar highlights that state's incidents and clicking it zooms to them.

What it shows off

  • "charts": two chart panels, docked right and bottom, each linked to layers[0]
  • "palette" left at inherit: the bars take the map's category colours, so a state looks the same in both
  • "topN": 10 with the rest grouped as Other, matching the map's ten categories
  • "theme": "futuristic": the HUD chart look on a dark skin and basemap
  • A readable #map=json: link that a chat-only model can write by hand, with no record data in it

Ask a chatbot

Any chatbot can write this one; it needs the layer's field names, which it can read with ?f=pjson or be given:

Make a GISMap Online (https://gismap.online) link of current U.S. wildfire incidents with a linked chart dashboard. Layer: https://services9.arcgis.com/RHVPKKiFTONKtxq3/ArcGIS/rest/services/USA_Wildfires_v1/FeatureServer/0. Colour the points by POOState (a "categories" renderer, maxCategories 10). Add two charts in the map spec's "charts" list: a bar chart "Incidents by state" grouped by POOState, counting features, top 10, docked right; and a compact column chart of DailyAcres summed by IncidentTypeCategory (WF is wildfire, RX prescribed fire), docked bottom. Use the futuristic chart theme, the dark-analytical skin and the dark-gray-vector basemap. Write it as one map-v1 spec (https://gismap.online/schemas/map-v1.schema.json), URI-encode it after https://gismap.online/#map=json: and give me the link. Do not put any counts in the link; the app computes them.

For a code-running agent

An agent can check the fields, validate the charts with the map and make the link. A chart whose field or layer is wrong is left out with a warning, so read the issues before sharing.

import { sources, mapSpec } from "https://gismap.online/js/gismap-core.js";

const url = "https://services9.arcgis.com/RHVPKKiFTONKtxq3/ArcGIS/rest/services/USA_Wildfires_v1/FeatureServer/0";
const { fields } = await sources.inspect(url); // POOState, IncidentTypeCategory, DailyAcres…
const spec = {
  version: 1, basemap: "dark-gray-vector", skin: "dark-analytical",
  layers: [{ url, renderer: { type: "categories", field: "POOState", maxCategories: 10 } }],
  charts: [
    { type: "bar", title: "Incidents by state", layer: 0, dimension: "POOState", style: { topN: 10, theme: "futuristic" } },
    { type: "column", layer: 0, dimension: "IncidentTypeCategory", measure: { field: "DailyAcres", aggregation: "sum" }, placement: "bottom", size: "compact" },
  ],
};
const { valid, issues } = mapSpec.validate(spec); // a chart with a bad field or layer is reported here
const { url: link } = await mapSpec.createLink(spec, { compress: false }); // the readable #map=json: form

In a running GISMap Online page, gisMapOnline.mapSpec.fromCurrent() writes the open chart panels back into charts, so a dashboard made in the app can be shared the same way.

Check before you share

  • The incidents are a live feed: counts and acres change through the day, and the chart shows what the layer holds when the link is opened.
  • Incidents include prescribed fires (IncidentTypeCategory RX) as well as wildfires (WF); filter with "where": "IncidentTypeCategory = 'WF'" for wildfires only.
  • DailyAcres is empty for many incidents, so the acres chart sums only the incidents that report it.
  • POOState is the state of the point of origin, written like US-CA.
